# Domain Docs

Projektet använder en gemensam domänkontext, eftersom det är en enda klientapplikation utan separata paketkontexter.

## Before exploring

- Läs `CONTEXT.md` i projektroten om den finns.
- Om en framtida `CONTEXT-MAP.md` finns, följ den till relevanta domänkontexter.
- Läs tillämpliga arkitekturbeslut under `docs/adr/` och, i ett eventuellt framtida projekt med flera kontexter, respektive kontexts egna ADR:er.
- Om dokumenten saknas, fortsätt utan att göra avsaknaden till ett hinder. Skapa inte tomma domändokument enbart för att denna setup genomförs.

## Vocabulary and decisions

Använd ordlistans termer där en ordlista finns. Tills vidare följer specifikationer och ärenden projektets befintliga termer, exempelvis lobby, värd, gäst, deltagare, match, runda, svar, matchpoäng, timeout, avhopp och ELO.

Om ett förslag strider mot ett befintligt ADR ska konflikten anges uttryckligen. Saknade begrepp eller nya domänbeslut kan dokumenteras när de faktiskt avgörs; detta dokument föreskriver ingen separat omstrukturering.
